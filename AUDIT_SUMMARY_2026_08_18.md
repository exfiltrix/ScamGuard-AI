## 🔴 Критичные находки (блокируют запуск)

### 1. **Утечка живых секретов в git** (SECURITY)

- **Содержимое:**

  - `OPENAI_API_KEY=AIzaSyB1gLestfL...` (живой Google API-ключ, ошибочно подписан)
- **Статус:** Публичен с коммита `e3eb1d1` (2026-04-12)
- **Действие:** Требуется немедленный отзыв в BotFather и перевыпуск ключей в Cloud Console

### 2. **Скоринг немонотонный** (CORRECTNESS)
- **Строка:** `pipeline.py:763` `if component in self.weights and score > 0:`
- **Эффект:** Модуль, вернувший 0 («ничего не найдено»), выбрасывается из знаменателя
- **Результат:** Более чистый LLM-вердикт *повышает* итоговый риск
- **Пример:** `{nlp:5, rules:60}` → 29 (LOW), `{nlp:0, rules:60}` → 60 (HIGH)
- **Категория:** Bugs in scoring logic that produce false verdicts

### 3. **API полностью открыт** (SECURITY)
- **Уязвимость:** IDOR на `/api/v1/message/{id}` и `/api/v1/history/{user_id}`
- **Эффект:** Перебором выгружаются все приватные сообщения пользователей (в БД 109 реальных)
- **Масштаб:** Все 13 эндпоинтов без аутентификации, CORS `allow_origins=["*"]` + `allow_credentials=True`
- **Категория:** Privat data exposure through sequential integer PKs

### 4. **Рейт-лимиты не реализованы** (SECURITY + ECONOMICS)
- **Объявлено:** `config.py:35` `rate_limit_per_minute: 10`
- **Используется:** Нигде (grep по коду = 0 результатов)
- **Эффект:** Один пользователь может полностью исчерпать все 5 Google API-ключей за минуты
- **Категория:** Quota exhaustion DoS

### 5. **SSRF уязвимость** (SECURITY)
- **Файл:** `parser.py:31-32`
- **Код:** `httpx.get(user_url, follow_redirects=True)` без allowlist схем и блокировки приватных IP
- **Достижимо из:** `analyze_url` в боте (`telegram_bot.py:1449-1506`)
- **Целевые хосты:** IMDS (`169.254.169.254`), localhost, внутренние сервисы
- **Категория:** Read SSRF via cloud IMDS and localhost

### 6. **Точность детекции не измеряется** (PRODUCT)
- **Функция:** `GET /api/v1/evaluation` (`main.py:377-427`)
- **Возвращает:** Захардкоженные precision 0.87 / recall 0.93 / F1 0.90
- **Комментарий:** `"For demo purposes, return summary and metrics. In production, you would run actual predictions here"`
- **Реальность:** Модель не запускается ни разу; это выдуманные числа
- **Риск:** Для стартапа это misrepresentation при due diligence

### 7. **Деградация в обман** (SAFETY)
- **Scenario:** Gemini quota исчерпана → `gemini_analyzer.py:332-363` fallback на 7 русских ключевых слов
- **Результат:** score 30 возвращается пользователю как вердикт
- **Проблема:** Структурно неотличим от реального анализа; `details["module"]` помечает fallback, но никто не читает
- **Категория:** False reassurance when AI fails silently

## 🟠 Крупные архитектурные проблемы

### 8. **66% кода — дубликаты** (MAINTAINABILITY)
- **Файл:** `pipeline.py` (981 строк)
- **Проблема:** 4 почти идентичные точки входа (analyze, analyze_listing, quick_check, analyze_message)
- **Дублирование:** Хвост скоринга повторён 4 раза (`:134-162`, `:272-300`, `:496-527`, `:707-737`), блоки обработки исключений 4 раза
- **Мёртвый код:** 330 строк (`send_quick_result`, `process_deep_analysis`, `run_deep_analysis_for_message`, callbacks)
- **Коллизия:** При любом исправлении скоринга надо менять в 4 местах или функция молча не применится

### 9. **Двойная система эскалации** (CORRECTNESS)
- **Слой 1:** `_calculate_weighted_score` применяет 5 порогов (`:779-791`)
- **Слой 2:** `_apply_safety_floor` применяет 12 порогов (`:808-887`)
- **Результат:** Взвешенное среднее декоративно; реальный вердикт из таблицы магических чисел
- **Примеры ложных HIGH:** `"context"` flag на каждом успешном grounding → floor 45; любой домен, не подтверждённый как "официальный" → floor 65 (`.shop` = HIGH RISK)

### 10. **Одна точка входа, но 4 кодовых пути** (TESTING)
- **Живая:** `deep_analyze` (через бот) — ОДНА точка
- **Мёртвые:** `analyze_listing` (листинг-продукт), `quick_check` (удалён из flow), `analyze_message` (legacy v1)
- **Тесты:** Мокируют весь пайплайн, не тестируют скоринг вообще (0% coverage на `pipeline.py`)

### 11. **Ни одного доверенного источника истины** (OPS)
- **Скоринг:** 40+ магических чисел без документации и калибровки
- **Пороги:** дублированы в 5 местах (pipeline, telegram_bot, gemini_analyzer)
- **Модули:** sequential I/O вместо параллельного (URL-анализатор делает 5 DNS+WHOIS запросов серийно = до 65 с на сообщение)
